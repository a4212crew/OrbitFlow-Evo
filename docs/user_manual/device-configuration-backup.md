# Device configuration backup — operator manual

**Script:** `scripts/device_configuration_backup.py`. **Purpose:** capture running configuration from approved Excel targets into local sensitive backup files. This is a read-only device operation but its outputs contain secrets; restrict storage and access.

## Prerequisites and safety
Run from the repository root with Python 3.11+, installed `requirements.txt`, `PYTHONPATH=src` if required, and an authenticated `tsh` profile. The input workbook contains approved device targets; credential material must not be committed. Provide all four required Teleport routing options: `--proxy`, `--cluster`, `--bastion-host`, `--bastion-user` (strings). Linux Teleport key/certificate file paths may be required; supply `--teleport-key-path` and `--teleport-cert-path` (optional paths, default unset). No script here performs configuration apply.

## Inputs and defaults
Required positional `excel_path` (Excel filename) and four required Teleport routing strings. Optional paths: `--teleport-key-path`/`--teleport-cert-path` (unset), `--inventory-path` (`data/inventory/inventory.json`), `--backups-dir` (`outputs/backups/configuration`), `--log-root` (`outputs/logs`), `--config` (`orbitflow.toml`). `--timeout` is a floating-point number of seconds, default `60.0` (configuration command timeout).

## Examples
Linux:
```bash
python scripts/device_configuration_backup.py outputs/devices.xlsx --proxy teleport.example.net:443 --cluster example-cluster --bastion-host example-bastion --bastion-user example-user --teleport-key-path "$TELEPORT_KEY_PATH" --teleport-cert-path "$TELEPORT_CERT_PATH" --timeout 60
```
Windows PowerShell:
```powershell
python scripts/device_configuration_backup.py .\outputs\devices.xlsx --proxy teleport.example.net:443 --cluster example-cluster --bastion-host example-bastion --bastion-user example-user --timeout 60
```
## Expected outcomes
Creates configuration backup artifacts under `outputs/backups/configuration` by default. Per-device connectivity failures can occur and should be investigated using backup logs and any failure workbook generated by the workflow. Treat the files as sensitive; do not upload to Issues or commit them. A run is not proof every device succeeded; inspect failures individually. No configuration is sent to devices. See [backup operations details](../../README.md#device-configuration-backup).

## Offline failure report recovery

Backup runs keep their existing capture files and `failed_devices.xlsx`. Shared
spool metadata is retained in `.processing/<run-id>/` beneath that same backup
folder. It contains sanitized failure columns and success markers; configuration
captures and supplied credentials never enter the spool. An interrupted collection
is incomplete and cannot be treated as a complete backup report. No automatic
recapture occurs.

The optional read-only API is
`orbitflow.configuration_backup.recover_failed_devices(run_path, output)`.
Both arguments are required paths: `run_path` selects the retained processing run,
and `output` selects the destination XLSX. It returns that destination `Path`.
The single `Failed Devices` sheet retains the six existing columns; retained
failures are emitted in target-input order. A completed
collection is required. Export failures retain the spool and existing report;
retry atomically replaces the destination without connecting. Wrong tasks,
incomplete/corrupt outcomes and filesystem errors fail explicitly. Spool status
records consuming/consumed/output_failed accurately. Keep raw capture access
protected and manage retention through the existing shared spool lifecycle.

Linux, from the repository root (replace the two example paths):

```bash
PYTHONPATH=src python -c "from orbitflow.configuration_backup import recover_failed_devices; recover_failed_devices('BACKUP_RUN/.processing/RUN_ID', 'BACKUP_RUN/failed_devices.xlsx')"
```

Windows PowerShell:

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
python -c "from orbitflow.configuration_backup import recover_failed_devices; recover_failed_devices('BACKUP_RUN/.processing/RUN_ID', 'BACKUP_RUN/failed_devices.xlsx')"
```

The optional recovery API leaves menus/default arguments unchanged as required
by Issue #162. Automated tests use synthetic safe failure metadata and prohibit
connections, including export failure/retry. Actual captures and native Windows
validation remain owner-controlled and pending.
